# 两套 CLI 使用的任务说明

你是 Wordiff 中文产品文案编辑。这是一个让作者核对 AI 改写的中文文本比对工具。用户厌烦了空泛、故作深刻、对仗口号和莫名其妙的问句，希望一眼知道能做什么、怎么用、怎么看结果。目标：去除 AI 味，直接、具体、自然，不用“赋能、有迹可循、意思走远、原来的痕迹”等修辞。读者是普通作者，不一定懂算法。
用户反馈原话：“文字变了 意思呢？”非常 AI，应该表达“受够了 AI 改写，不知道应该看哪些？导入原始需求和 AI 输出，获取多种比对效果：Git Diff、逐词比对、按句语义比对，让 AI 修改不再痛苦！”
明确名称：把“把长文拆开，逐行对照”改为“类 Git Diff 比对模式”；把“哪些词，还留着原来的痕迹”改为“切词比对模式”；“怎么算”改为“算法原理”；“怎么看”改为“比对方式”；解释 Dice 是什么意思；删除“让每一处改写，有迹可循”之类口号。
注意事实：当前是固定样本演示（原文+低中高三种改写），尚未支持导入或上传，不能承诺此功能；改写正文、原文与指标数据是算法输入，不可润色，否则破坏比对。只改产品文字及说明文档。语义相似度不能断定原意不变或事实正确。
四种模式统一叫：审阅模式、类 Git Diff 比对模式、切词比对模式、按句语义比对模式。保留路由、代码标识、数据、链接、参数和算法行为。
Dice 事实依据：词语计数取交集（每个词取两句出现次数较小值），按 IDF 加权，得分为 2×交集权重÷两句总权重；字符二元组先去空白，按相邻两个字符组成集合，得分为 2×共同片段数÷两句片段总数。综合 65% 词语+35% 二字片段，仅用于寻找原句，不是词语着色分数本身。IDF 使在原文句子中较少出现的词权重更高。
任务：逐一审核下面全部文件中的所有面向读者的文字（标题、段落、按钮、选项、图例、提示、错误、占位符、aria-label、alt、弹窗、页脚、SEO等），另覆盖 README/方法/开发/部署/贡献文档说明。已经直白准确的短标签可以保留，不强行为每句话改写。代码中的文章、事实注释内容保留原意，隐私条款保留全部信息，勿增加承诺。只提供文案替换建议，不操作工具、不读取文件、不运行命令、不修改文件。
输出一个完整 JSON 对象，不要 Markdown 围栏：
{"editorial_summary":"整体判断", "replacements":[{"file":"文件相对路径","old":"源文件中可精确匹配的原始连续文字片段","new":"替换文字","reason":"简短理由"}], "coverage":[{"file":"每一个文件的路径","reviewed":"已审阅的文字范围","keep":"保留哪些内容及原因"}]}
同一文件各 old 片段不得重叠；old/new 不含不相关代码，只替换真实存在的连续文字。允许 old 是含 JSX 的一段以替换跨行标题，保持 JSX 正确。多个位置相同文案用一条替换。请给出全面成稿，不要只举例。严禁在 new 中增加换行导致单引号字符串失效。


## 补充说明

主任务向两套 CLI 提供了完全相同的 14 个文件全文；另提交反馈 API 文案进行补充审阅。原文、三个改写样本与计算数据不在润色范围内。

初始说明中“字符二元组先去空白”有误。这是任务说明的错误，不作为两模型优劣判断依据。补充任务已告知两个 CLI：实际代码直接使用句子全文，包含标点和空格。最终稿按 `scripts/analyze.py` 核实并纠正了该表述。
