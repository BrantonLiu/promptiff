# 全站文案润色对比

本轮更推荐 **Kimi 作为产品文案的起稿版本**。它的首页表达更接近“核对 AI 改写”这个用途，句子也比 GLM 的“一处一处来”自然。**GLM 对指定命名的执行更准确**，反馈服务未配置时的提示也更合理。最终页面结合两稿，并按用户意见和实际代码做了人工复核，没有直接照搬任一整稿。

本轮文案在 `codex/plain-language-copy` 分支完成审稿。工作开始前已有的首页、样式、文档、预览图和部署配置修改均保留。

## 对比依据

两个 CLI 收到同一份产品背景、用户原话、功能边界、统一名称和 14 个文件全文，另审阅了反馈 API 提示。要求是去除 AI 味，保留事实和操作含义，已清楚的文案可以不改。输入材料不含账号密钥或用户反馈数据。

- Claude CLI：实际返回模型为 `glm-5.3`，主稿 47 条替换建议，14 个文件的覆盖说明；另有 4 条 API 建议。
- Kimi CLI：使用本机默认配置 `kimi-code/k3`，主稿 36 条替换建议，14 个文件的覆盖说明；另有 4 条 API 建议。
- 两稿的原文替换片段均可在提供的源文件中找到。数量差异也来自拆分方式，不能据此判断文案质量。

## 关键文案逐项比较

| 位置 | GLM 建议 | Kimi 建议 | 最终采用与理由 |
| --- | --- | --- | --- |
| 首页主标题 | 核对 AI 改写，一处一处来。 | AI 改写的稿子，逐处核对改了什么。 | **受够了 AI 改写，不知道该看哪里？** 按用户提供的痛点表达重写；GLM 的后半句仍是口号，Kimi 更具体，但没把痛点放到标题。 |
| 工作区标题 | 核对 AI 改写，一处一处来 | AI 改写之后，到底改了什么？ | **核对原文与 AI 改写**。操作页面用直接标题即可。 |
| Diff 功能标题 | 类 Git Diff 比对模式 | 原文在左，改写在右，逐行对照。 | 采用 GLM，符合用户明确指定的名称。 |
| 切词功能标题 | 切词比对模式 | 逐词检查原文用词保留了多少。 | 采用 GLM；具体用途放在说明段落。 |
| 首页结尾 | 打开比对页面，逐处检查。 | 打开样本，开始比对。 | **打开示例，检查具体改动。** 延续两稿的行动指引，不再加“有迹可循”。 |
| 语义图例 | 句子级 · embedding 余弦相似度 | 句子级 · 语义向量 | 采用 Kimi，普通读者不需要在图例里先理解英文术语；算法细节保留在说明中。 |
| 方法弹窗标题 | 比对方法与数据说明 | 这个演示在比较什么 | **算法原理与样本说明**。采用 GLM 的直接命名方向，并对应用户要求。 |
| 反馈服务未配置 | 反馈服务尚未配置，暂时无法提交反馈。 | 保留“反馈服务尚未配置，请稍后重试。” | 采用 GLM。配置缺失不会因为用户等一会儿而解决。 |
| Dice 解释 | 内容完整，但把定义、权重和公式塞进一个长步骤 | 稍短，也仍把很多算法细节放在一句里 | 首页分成找原句、解释重合度、给词着色三个步骤；方法文档另给 0.75 的算例。 |
| 隐私、登录、部署文档 | 多数保留 | 多数保留 | 简短准确的内容保留。人工删去隐私页“此说明不意味着这些技术日志不存在”这种重复辩解，保留前文的日志处理说明。 |

## 两稿的遗漏与人工修订

两稿都保留了部分“四种视角，同一份原稿”等宣传式短句；最终稿改为“功能介绍”，并清理了工作区的实验口吻、反馈问卷的开场套话、未翻译的关闭按钮和分享图片里的旧标题。

初始任务说明误写“字符二元组先去空白”，两稿都沿用了它。这是输入材料的问题，不计入模型优劣。补充任务已告知两个 CLI；最终实现按 `scripts/analyze.py` 核对：字符片段包含标点和空格，重复片段在集合中只计一次。词语匹配采用词频计数和 IDF 权重。65% 与 35% 仅用于寻找原句，词语颜色另按顺序、复用位置和字形相似度计算。

首页没有采用“导入原始需求和 AI 输出”的功能承诺，因为当前只支持内置样本。标题保留用户的痛点，按钮明确为“查看比对示例”，旁边注明“暂不支持导入”。
